# Once every component is vendored, the component sources are the repo's and the design data stays the artifact's

ADR 0003 left the artifact the source of truth for everything it holds: a visual change is made there first and reaches the repo as a deliberate re-copy ticket, never the reverse. It was written on 2026-10-24, before the first component was copied, and treated the component sources as part of the design. Anthropic's documented flow for Claude Design runs the other way for a design system that already exists as React components (the support articles "Get started with Claude Design" and "Set up your design system in Claude Design", read on 2026-10-26): the code is the source and `/design-sync` republishes it into the design system, Claude Design checks its output against that system, and `/design` and the Export menu's "Send to local coding agent" hand screens to Claude Code, which builds them from the components the repo already has; nothing in it pulls a component library out of a design system into code, so the copy of ADR 0003 stays the right way to seed `packages/ui`. Once ticket #11 lands the copy is complete, and under ADR 0003 every later component fix (the accessibility findings the axe pass of #12 raises, a React 19 type, a keyboard bug) would be made in a bundle on React 18 that the app never runs, then brought back through the conformance pass the package README describes, while the canvas kept rendering components the app no longer had. We split the source of truth by kind from the commit that closes #11: the component sources, the helpers beside them and `components.css` are the repo's, fixed in `packages/ui` under its types, lint and tests and published up to the artifact, never copied down again; the design data stays the artifact's and comes down by re-copy as before: `tokens.json` and so `tokens.css`, the brand book, the glossary, voice, messages and formats, the icons, logos and favicons, the font, and the seven page and five document examples. The line is the one between a decision and its implementation: a colour, a size, a word, an icon or a page's order of parts is decided in the artifact; how a control behaves is code. This amends the last sentence of ADR 0003, and with it spec #9's decision "The artifact stays the source of truth" and its story 26; the rest of ADR 0003 stands, the words sentence included.

## Considered options

- **The artifact first for everything** (ADR 0003 as written): one place to look, and the designer's tool leads; but a component fix is a round trip through a bundle on React 18 the app never runs and a conformance pass applied by hand, the artifact's own types are not checked (its documentation says so), and the canvas and the app drift apart between re-copies.
- **The repo first for everything**, tokens and words included: one direction, and `/design-sync` reads tokens from code; but colours, sizes, words and examples are decided by the person designing, in the tool made for it, their re-copy is a file copy with no conformance pass, and the glossary already flows from the design system into `packages/i18n` by its own rule (domain.md §7.4).
- **Split by kind** (chosen): the artifact decides, the repo implements; every file has one owner and one direction.

## Consequences

- From the commit that closes #11, a change to a vendored source is a repo change: made in `packages/ui`, reviewed there, and carried to the artifact by a sync up. `source.json`'s version is from then on the fork point of the sources and the version of the data files, which keep being re-copied by the procedure the package README gives, minus the conformance pass they never needed.
- The sync up is `/design-sync` once it targets design system artifacts. On 2026-10-26 the DesignSync tool and the `claude_design` server still address the standalone store at claude.ai/design, which lists no vetora system and closes on 2026-12-14, while the Artifact tool lists the Vetora design system beside SQUAD; until then the changed sources are published into the artifact's `project/components/src/` and `project/components/bundle.css` with the Artifact tool, as `project/glossary.md` was on 2026-10-24. Whether the canvas rebuilds `bundle.js` from published sources is verified at the first sync; if it does not, rebuilding it is a step of that sync.
- `docs/design.md` (ticket #13) names the owner of each kind, the fork point, and a ledger of the repo's changes to the sources with the date each reached the artifact, in place of a divergence list; the package README's re-copy section becomes the two procedures; `packages/ui/AGENTS.md` carries the rule.
- The eleven Biome rules the pass of ADR 0003 turned off for `packages/ui/src/*.tsx` are the repo's to turn back on as each component is fixed. An accessibility fault found by #12's axe check is fixed in the repo; a failing contrast pair is still fixed in the artifact's tokens (#11), since the colour is the decision.
- Screens from feature 5 on are drafted against the Vetora design system with `/design`, set as the default design system in Claude's settings so the skill picks it without asking, or handed off from one of the page examples with "Send to local coding agent", and are implemented in `apps/clinic-web` by composing `@vetora/ui`. A screen that needs a new component gets it as a repo change, synced up, not as an artifact change copied down.
- A UI word keeps the glossary's rule: added to the design system glossary first, in all three languages, then into `packages/i18n` (domain.md §7.4).
