# /develop stack & architecture: scaffold notes (2026-10-22)

The scaffold landed on 2026-10-22 (scope feature 1, box "Scaffold from the decision" ticked; spec 0001 In Progress). These are the choices made while building that the spec did not spell out, for `/audit`, `/sync`, and the next `/develop` runs.

- **Boundary with feature 3 (data model, spec 0002):** its build plan owns the control and practice migration sets, `control.practice`, the `migrate` and `provision-practice` commands, the two drizzle-kit configs, and the schema module skeleton. The scaffold ships only the local database (`vetora`, UTF8, ICU root collation `und`, UTC), the three base roles (`vetora_migrator` with CREATEROLE, `vetora_app`, `vetora_backup`; CONNECT revoked from PUBLIC), and a Drizzle client with pooled and direct `pg` pools (`apps/api/src/platform/db.ts`). No `migrate.ts` and no Kamal pre deploy hook yet; both land with feature 3 (the hook is described in `apps/api/config/deploy.yml`).
- **Lint stripped from the Vite template** (`.oxlintrc.json`, the `lint` script, the `oxlint` dependency): `/audit` and feature 2 choose the linter. `packages/config` holds only TypeScript config for the same reason.
- **TypeScript pinned to 6.0.x** through the pnpm catalog in `pnpm-workspace.yaml` (openapi-typescript and drizzle-kit do not support the TypeScript 7 compiler API). openapi-typescript 7.13 warns about its `^5.x` peer but generated fine on 6.0.3.
- **The API serves its routes under `/api` itself** and kamal-proxy keeps the prefix (`strip_path_prefix: false`); Vite proxies `/api` in development. `/up` is a cheap liveness route for the proxy; `/api/health` is the one that touches the database.
- **Errors are problem details JSON** (`apps/api/src/platform/problem.ts`), Postgres `detail`/`hint`/`where` are dropped before logging or reporting (`scrubError`), and zod validation failures use the same shape through the OpenAPIHono default hook.
- **Web runtime config** comes from `/config.json`, written by the nginx container at start from `SENTRY_DSN_WEB`, `APP_ENV`, and `KAMAL_VERSION` (`apps/clinic-web/docker/10-runtime-config.sh`), so nothing is baked into the image. Source maps are hidden, uploaded only in CI, deleted from the image, and refused by nginx.
- **Language choice** in the web app is per browser (`localStorage` key `vetora.language`, default `az`); the practice default language arrives with practice settings.
- **Local test credentials** (the three roles' passwords) live only in `infra/postgres/init/01-vetora.sql` and `apps/api/.env.example`; `infra/digitalocean.sh` generates real ones into `infra/.state/` (git ignored).
- **Not yet done, by design:** the hosted deploy. `infra/digitalocean.sh` is written but has never run; the Kamal destination files carry placeholders (`STAGING_DROPLET_IP`, `staging.vetora.example`); the staging workflow is inert until the `STAGING_READY` repository variable is set. The scope's "deploys once to a hosted environment" is proven by `/check verify` after that first deploy.
