# apps/clinic-web

## Overview

The web app for clinic staff: React 19 on Vite 8, rendered in the browser and served from the same origin as the API (`/api`). Routes are files under `src/routes/`, server state goes through TanStack Query, the API is called through the typed client from `@vetora/contracts`, and every piece of screen text comes from `@vetora/i18n`. The design system comes from `@vetora/ui` (ADR 0003): its stylesheet is imported once in `src/main.tsx`; `src/index.css` is what remains of the placeholder and goes with the shell (ticket #12).

## Stack

- React 19, Vite 8 with `@vitejs/plugin-react`, TypeScript project references (`tsc -b`, `erasableSyntaxOnly`)
- TanStack Router 1 (file routes; `@tanstack/router-plugin` writes `src/routeTree.gen.ts`) and TanStack Query 5
- `openapi-fetch` over the generated `paths` type; i18next 26 with react-i18next 17; `@sentry/react` 11 and `@sentry/vite-plugin`
- Static files behind nginx 1.29 in the image (`Dockerfile`, `docker/`), rolled out with Kamal (`config/deploy.yml` and a destination file per environment)

## Key files

| File | Owns |
|---|---|
| `src/main.tsx` | Mounts the app: the `QueryClient`, the router, the i18n side effect import, error reporting |
| `src/routes/__root.tsx` | The shell: header with the language switcher, then `<Outlet />` |
| `src/routes/index.tsx` | The home route, which mounts `StatusPage` |
| `src/pages/StatusPage.tsx` | The status page: polls `/api/health` every 30 s and shows the brand book's page states with `@vetora/ui`: a `Skeleton` with the region `aria-busy` while the first check is in flight, a danger `Banner` first in the page with "Try again" when the API is down, a success `Badge` with the version when it is up. `StatusPage.test.tsx` beside it is the DOM test of the three states |
| `src/routeTree.gen.ts` | Generated by the router plugin from `src/routes/`; never edited by hand |
| `src/api/client.ts` | `api`, the typed client on `window.location.origin` (same origin, spelled out so the DOM tests can run it) |
| `src/i18n.ts`, `src/i18next.d.ts` | i18next setup, the per browser language (`localStorage` key `vetora.language`, default `az`), typed translation keys |
| `src/sentry.ts` | Reads `/config.json` at runtime and starts Sentry with every collection option off |
| `src/test-setup.ts` | jest-dom's matchers and Testing Library's cleanup, loaded by the `test` block of `vite.config.ts` |
| `vite.config.ts` | Router plugin before React, the `/api` dev proxy to `:3000`, hidden source maps uploaded only when `SENTRY_AUTH_TOKEN` is set (CI), the `test` block (jsdom, the setup file) |
| `docker/nginx.conf`, `docker/10-runtime-config.sh` | `/up`, caching rules, 404 for `.map` files, `index.html` for every route; `/config.json` written from the container environment at start |

## Commands

```bash
pnpm --filter @vetora/clinic-web dev        # Vite on :5173; the API must run too (pnpm dev at the root starts both)
pnpm --filter @vetora/clinic-web build      # tsc -b, then vite build to dist/
pnpm --filter @vetora/clinic-web typecheck  # tsc -b
pnpm --filter @vetora/clinic-web preview    # serves the built dist/
```

## Conventions

- A route is a file under `src/routes/` using `createFileRoute`; the plugin regenerates `routeTree.gen.ts` during dev and build.
- The API is reached only through `api` from `src/api/client.ts`, so every call is typed against the OpenAPI document; server state lives in TanStack Query (`useQuery` with array keys), not in component state.
- No screen text in components: every string is a key in `packages/i18n` (`t('health.title')`) that exists in `az`, `ru`, and `en`; `document.documentElement.lang` follows the chosen language.
- Runtime values (Sentry DSN, environment, release) come from `/config.json`, never from `import.meta.env` at build time, so one image serves every environment.
- No personal data in URLs: search parameters hold only filters that are not personal (status, dates, location); names and phones travel in request bodies (spec 0001, "API conventions").
- Imports carry no extension (bundler resolution); `verbatimModuleSyntax` and `erasableSyntaxOnly` are on, so types are imported with `import type`, and enums, namespaces, and parameter properties are out.
- A route file exports only `Route`; the page it mounts lives under `src/pages/`, so a test renders the page without the router (the router joins the DOM test with the shell, ticket #12).
- `src/index.css` is the placeholder's remainder until the shell (ticket #12); styling comes from `@vetora/ui`'s stylesheet and is not written here.
- Tests go beside the code as `*.test.tsx` and run with `pnpm test` at the root in jsdom (the `test` block of `vite.config.ts`) with Testing Library: `@testing-library/react`, `user-event`, and jest-dom's matchers through `src/test-setup.ts`. A page test renders the page with a `QueryClient` and the real translations (`import '../i18n'`), stubs `fetch` inside `vi.hoisted` (the typed client captures `globalThis.fetch` when it is created), and asserts what a person sees: roles, names, text.

## Gotchas

- `@vetora/contracts` and `@vetora/i18n` resolve from their `dist/`: after editing either, rebuild it (`pnpm --filter @vetora/i18n build`); `pnpm dev` builds them once and does not watch them. `@vetora/ui` is watched: its `dev` script (`tsc --watch`) runs under `pnpm dev`, so a component edit reaches the browser without a rebuild.
- jsdom stays on 29 until the local Node reaches 24.15, jsdom 30's floor (`.nvmrc` says 24; the machine had 24.14.0 on 2026-10-24).
- Source maps are hidden and must never reach the image or the browser: the Dockerfile deletes `*.map` after the build and nginx answers 404 for them.
- Client side routing: nginx serves `index.html` for unknown paths; hashed assets are cached for a year, `index.html` and `/config.json` are not.
- Browsers lack Azerbaijani locale data for dates and numbers; the design system ships its own formatters, and the design system work decides how this app uses them. `Intl.PluralRules` does know `az` and `ru`, which is what i18next uses for plurals.
